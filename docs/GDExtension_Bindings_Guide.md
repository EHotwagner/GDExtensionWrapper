# GDExtension Binding Generation Guide

This guide outlines the structure of the `extension_api.json` file and the process of generating language bindings for Godot 4.

## 1. What is `extension_api.json`?

The `extension_api.json` file is a machine-readable description of the entire Godot Engine API. It is generated by the engine itself (using `godot --dump-extension-api`) and serves as the source of truth for binding generators.

### Key Sections

*   **`header`**: Contains version information (e.g., `version_major`, `version_minor`, `version_full_name`) and the floating-point precision (`single` or `double`).
*   **`builtin_class_sizes`**: Lists the size in bytes of builtin types (like `Vector3`, `String`, `Variant`) for the target build configuration. This is crucial for allocating memory correctly in the target language.
*   **`global_constants` & `global_enums`**: Defines engine-wide constants and enumerations (e.g., `Error`, `Side`) that are not tied to a specific class.
*   **`builtin_classes`**: Describes fundamental types (Value Types) such as `Vector2`, `Color`, `String`, and `Array`.
    *   Includes `constructors`, `operators` (e.g., `+`, `==`), `methods`, and `members`.
    *   These types are usually mapped to native structs or primitives in the target language.
*   **`classes`**: Describes Godot Objects (Reference Types) like `Node`, `Resource`, `Object`.
    *   Includes `inherits` (parent class), `methods`, `properties`, `signals`, and `enums`.
    *   These are accessed via pointers/handles in the GDExtension API.
*   **`utility_functions`**: Global helper functions like `print`, `sin`, `cos`, `clamp`.
*   **`native_structures`**: Defines C-compatible structs used in specific high-performance APIs (e.g., `PhysicsServer2DExtensionMotionResult`). The `format` field describes the C struct layout.

## 2. The Binding Generation Process

Creating bindings involves reading this JSON and generating code that bridges your target language with Godot's C API.

### A. Parsing the JSON
The first step is simply loading the JSON file into a data structure in your generator tool. You will need to traverse the `classes` and `builtin_classes` arrays extensively.

### B. Mapping Types
You must define a mapping between Godot types and your language's types:

| Godot Type | Concept | Target Language Strategy |
| :--- | :--- | :--- |
| `int`, `float`, `bool` | Primitives | Map to native primitives (e.g., `int64_t`, `double`, `bool`). |
| `Vector3`, `Color`, etc. | Builtin Classes | Generate structs matching the size defined in `builtin_class_sizes`. |
| `String`, `Array` | Complex Builtins | Wrap the opaque pointers provided by Godot's API. |
| `Node`, `Object` | Classes | Generate wrapper classes that hold an internal `Object*` or opaque handle. |
| `enum::Error` | Enums | Generate native enums. |

### C. Handling the GDExtension Interface (C API)
Godot exports a C API (defined in `gdextension_interface.h`) which provides function pointers for all engine interactions.
*   **Initialization**: Your library must export an entry point `godot_gdextension_entry`.
*   **Function Pointers**: You receive a struct of function pointers (e.g., `get_proc_address`). You use this to load all other API functions (e.g., `classdb_construct_object`, `variant_new_copy`).

### D. Registering Classes and Methods
To make your custom classes visible to Godot:
1.  **Class Creation**: Use `classdb_register_extension_class` to tell Godot about your new type.
2.  **Method Binding**: Use `classdb_register_extension_class_method` to expose functions.
3.  **Property Binding**: Use `classdb_register_extension_class_property` to expose variables to the Inspector.

## 3. Existing Binding Generators

Studying existing projects is the best way to learn.

*   **[godot-cpp](https://github.com/godotengine/godot-cpp)**: The official C++ bindings.
    *   *Approach*: Uses a Python script (`binding_generator.py`) to parse the JSON and output C++ headers and sources. It heavily uses templates to handle type conversion automatically.
*   **[godot-rust](https://github.com/godot-rust/gdext)**: The Rust bindings.
    *   *Approach*: Uses a Rust build script (build.rs) to parse the JSON and generate Rust code. It leverages Rust's macro system for a developer-friendly API.

## 4. Steps to Implement a Generator

Here is a high-level roadmap for writing your own generator:

1.  **Scaffold the Project**: Create a console application (the generator) and a library project (the runtime/bindings).
2.  **Load API Data**: Read `extension_api.json` into memory.
3.  **Generate Enums**: Iterate through `global_enums` and `classes[].enums`. Output them as native enums to avoid magic numbers.
4.  **Generate Builtin Wrappers**:
    *   For each `builtin_class`, generate a struct/class.
    *   Generate method bindings by looking up the method hash in the JSON.
    *   *Example*: For `Vector3.length()`, generate code that calls the Godot API function `variant_call` or the specific `ptrcall` optimized function.
5.  **Generate Class Wrappers**:
    *   For each item in `classes`, generate a class that inherits from its parent wrapper.
    *   Store the `MethodBind` pointers statically. The JSON provides a `hash` for every method. You pass this hash to `classdb_get_method_bind` at runtime to get the function pointer.
6.  **Implement the Entry Point**: Write the boilerplate C code required to initialize the library and hand off control to your generated code.

### Key Concept: Method Hashes
In `extension_api.json`, every method has a `hash`.
```json
"name": "set_position",
"hash": 2436343242,
```
Your generated code uses this hash to ask the Godot engine for the function pointer to `set_position` for that specific class. This ensures version compatibility and safety.
